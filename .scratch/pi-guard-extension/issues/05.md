# 05 — 守卫模式路径白名单与 Bash 只读命令放行

## Problem Statement

当前守卫在 `guarded` 模式下拦截所有 `write`、`replace`、`bash` 工具调用，但项目中有几个合法路径（`.scratch/`、`docs/`、`CONTEXT.md`）在技能讨论结束后仍可能需要写入（如记录讨论产物、更新上下文）。一刀切拦截导致这些合法操作也被阻止。

此外，`bash` 工具全部拦截过于严厉——只读命令（`ls`、`cat`、`grep`、`git log` 等）不改变文件系统状态，不应被阻止。用户需要在 guarded 模式下仍能执行查询和查看操作。

## Solution

为守卫模式添加**路径白名单**机制：`write`/`replace` 工具在 guarded 模式下仍可写入白名单路径。同时将 `bash` 拦截策略从"全部拦截"调整为"只拦截写入性命令"，放行只读命令和 git 只读命令。

## User Stories

1. 作为一名项目维护者，当守卫激活时，我希望 AI 仍能向 `.scratch/` 目录写入讨论产物，以便记录技能对话的中间输出。
2. 作为一名项目维护者，当守卫激活时，我希望 AI 仍能向 `docs/` 目录写入文档，以便技能讨论后自动生成 ADR 或术语表。
3. 作为一名项目维护者，当守卫激活时，我希望 AI 仍能写入 `CONTEXT.md` 文件，以便更新会话上下文。
4. 作为一名项目维护者，当守卫激活时，我希望 AI 仍能执行 `ls`、`cat`、`head`、`grep`、`find`、`echo` 等只读 bash 命令，以便查看文件内容而不破坏文件系统。
5. 作为一名项目维护者，当守卫激活时，我希望 AI 仍能执行 `git log`、`git status`、`git diff`、`git show` 等 git 只读命令，以便了解仓库状态。
6. 作为一名项目维护者，当守卫激活时，我希望 AI 执行包含 `>`、`>>`、`sed -i` 等写入操作的 bash 命令仍然被拦截，以防止未经授权的修改。
7. 作为一名项目维护者，当守卫激活时，我希望 AI 向白名单之外路径（如 `src/`）的 `write`/`replace` 调用仍然被拦截，以保护项目核心代码。
8. 作为一名项目维护者，我希望 `CONTEXT.md` 精确匹配（不匹配 `CONTEXT.md.bak` 或 `docs/CONTEXT.md`），以避免意外放行不该放行的路径。
9. 作为一名项目维护者，当守卫激活时，我希望 AI 使用 `write` 工具向不存在的白名单子目录写入时能正常被放行（目录创建由 `write` 工具自身能力处理，不归守卫管）。
10. 作为一名项目维护者，我希望白名单路径列表在项目初始化时就包含 `.scratch/`，因为该目录始终存在。

## Implementation Decisions

### 路径白名单

- **默认白名单路径**（硬编码，暂不可配置）：
  - `.scratch/` — 前缀匹配（目录），匹配 `.scratch/` 下任意路径
  - `docs/` — 前缀匹配（目录），匹配 `docs/` 下任意路径
  - `CONTEXT.md` — 精确匹配（仅根目录下的 `CONTEXT.md`，不匹配 `CONTEXT.md.bak` 或 `docs/CONTEXT.md`）
- 匹配规则：路径归一化（去除首 `./` 前缀）后，目录路径以 `allowedPath` 为前缀，文件路径精确匹配
- `write` 和 `replace` 工具：guarded 模式下先检查 `event.input.path`，命中白名单则放行（返回 `undefined`），否则拦截

### Bash 命令拦截策略调整

从"全部拦截"改为**"拦截写入性命令"**：

- **放行**（只读命令）：
  - 文件查看：`ls`、`cat`、`head`、`tail`、`less`、`more`、`wc`
  - 搜索/查找：`grep`、`find`、`rg`、`ag`、`ffgrep`、`fffind`
  - 文件信息：`file`、`stat`、`du`、`df`、`ls -l`、`which`、`type`
  - 内容查看：`echo`（仅无重定向时）、`printf`（仅无重定向时）、`read`
  - 进程/状态：`ps`、`top`、`htop`、`uptime`、`date`、`cal`
  - 网络查看：`curl`（仅 GET/HEAD）、`ping`、`dig`、`nslookup`、`host`
  - Git 只读：`git log`、`git status`、`git diff`、`git show`、`git branch`、`git tag`、`git describe`、`git rev-parse`、`git ls-files`、`git stash list`
- **拦截**（写入性命令）：
  - 包含 `>`、`>>`、`<` 重定向符的命令
  - 包含 `|` 管道符后跟写入性命令的模式
  - 编辑/写入命令：`sed -i`、`awk -i`、`tee`、`dd`、`mkfs`、`mount`
  - 创建/删除：`touch`、`mkdir`、`rmdir`、`rm`、`mv`、`cp`、`ln`
  - 权限修改：`chmod`、`chown`、`chattr`
  - Git 写入：`git add`、`git commit`、`git push`、`git pull`、`git merge`、`git rebase`、`git reset`、`git checkout`、`git branch -d`、`git tag -d`、`git stash push`、`git stash drop`
  - 包管理写入：`npm install`、`npm publish`、`uv sync`、`pip install`
- 判断方式：基于命令前缀和参数模式的静态检查（不执行命令）
- 此策略是保守的——宁可拦截不确定的命令，也不放行可能有写操作的命令

### 状态机变更

`GuardMachine` 接口新增方法：

```typescript
interface GuardMachine {
  // ... 现有方法 ...

  /** 检查路径是否在白名单中。 */
  isPathAllowed(filePath: string): boolean;
}
```

### 路径归一化规则

- 去除开头的 `./` 前缀（`./.scratch/foo` → `.scratch/foo`）
- 不解析 `..` 穿越（`../guard/.scratch/foo` 不匹配 `.scratch/` 前缀）
- 不解析符号链接
- 不处理绝对路径（绝对路径默认不匹配任何白名单路径）

## Testing Decisions

### 测试原则

- 只测试外部可观测行为，不测试内部实现细节
- 核心测试接缝：**integration**（`index.test.ts`），覆盖完整的扩展事件处理流程
- `isPathAllowed` 作为 GuardMachine 内部方法，由 integration test 间接覆盖

### 测试场景（integration seam）

1. **guarded + write → 白名单路径** → 放行（`undefined`）
2. **guarded + write → 非白名单路径** → 拦截（`{ block: true }`）
3. **guarded + replace → 白名单路径** → 放行
4. **guarded + replace → 非白名单路径** → 拦截
5. **guarded + bash → 只读命令（`ls -la`）** → 放行
6. **guarded + bash → 写入命令（`rm -rf`）** → 拦截
7. **guarded + bash → 重定向命令（`echo foo > file`）** → 拦截
8. **guarded + bash → git 只读命令（`git status`）** → 放行
9. **guarded + bash → git 写入命令（`git commit`）** → 拦截
10. **normal 模式** → 所有工具正常放行（无变化）
11. **guarded + write → CONTEXT.md** → 放行（精确匹配）
12. **guarded + write → CONTEXT.md.bak** → 拦截（不应匹配）
13. **guarded + write → docs/CONTEXT.md** → 放行（由 `docs/` 前缀匹配命中，预期行为）
14. **guarded + write → `./.scratch/foo`** → 放行（归一化后匹配）

### 测试方式

- 复用已在 `index.test.ts` 中建立的 mock pi 和 mock ctx 模式
- 通过模拟 `input` + `agent_settled` 流程将守卫置为 guarded 状态，再触发 `tool_call` 检验结果
- 与现有测试风格保持一致

## Out of Scope

- 不支持 Windows 路径分隔符（`\`），仅处理 Unix 风格路径（`/`）
- 不支持用户自定义白名单路径（后续 issue 可加入配置化支持）
- 不支持白名单路径的 glob/wildcard 模式
- 不覆盖非标准工具名称（如 `my_custom_writer`），除非显式配置
- 不对 bash 命令做实际沙箱执行——仅基于静态文本模式判断

## Further Notes

- Bash 只读命令白名单采用保守策略：宁可误拦，不可漏拦
- Git 只读 vs 写入的区分命令列表参照常见 git 子命令分类
- 路径白名单的"配置化"留待后续 issue 实现，当前硬编码的默认值已满足项目需求
- 如果将来需要更精细的 bash 控制，可考虑引入 bash 命令白名单配置项
